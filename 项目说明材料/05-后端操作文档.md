# 后端操作文档

适用版本：2026-10-19 当前工作区，Spring Boot 3.5.16 / Java 21 / MySQL 8.4.6，数据库迁移至 V2。面向后端开发、部署维护和外部 API 调用方。示例凭证均为占位符。

## 1. 运行方式选择

| 目的 | 方式 | 注意事项 |
| --- | --- | --- |
| 完整运行管理平台 | Docker Compose 三服务 | 交付运行方式；仅发布前端端口 |
| 修改后端、断点调试，配合 Vite | 独立开发 MySQL + 宿主 Maven | 第 4 节提供开发覆盖配置，不改默认 Compose |
| 验证业务和认证 | Maven + Testcontainers | 自动创建独立真实 MySQL，需要 Docker |
| 验证 Nginx、登录、Key 和持久化 | 独立认证冒烟 Compose 项目 | 第 7 节；不能指向真实数据环境 |
| 外部服务只读接入 | HTTP API + X-API-Key | 无需管理员登录，需管理员提前发放 Key |

未注明其他目录的命令均在仓库根目录执行，主要使用 PowerShell。备份小节另标为 POSIX shell。不要将 .env、Cookie、密码、完整 Key 或数据库 dump 提交 Git。

## 2. 完整 Compose 部署与首次登录

### 2.1 准备配置

安装 Docker Engine/Desktop 与 Compose v2，使用 Linux 容器。首次创建配置：

```powershell
Copy-Item .env.example .env
```

若 .env 已存在，直接编辑，不覆盖。填写独立随机数据库密码、用户名和初始管理员密码；检查绑定地址、端口和来源。

| 环境变量 | 含义 | 默认/要求 |
| --- | --- | --- |
| FRONTEND_BIND | 前端宿主绑定地址 | 127.0.0.1；内网访问需配置实际受控绑定地址 |
| FRONTEND_PORT | 前端宿主端口 | 8088 |
| DB_NAME | 应用数据库 | 必填；示例 skill_platform |
| DB_USER | 应用账号 | 必填；示例 skill_app，不使用 root 运行应用 |
| DB_PASSWORD | 应用数据库密码 | 必填，无默认生产密码 |
| MYSQL_ROOT_PASSWORD | MySQL 初始化 root 密码 | 必填，与应用密码分开 |
| ALLOWED_ORIGINS | 逗号分隔的精确浏览器 origin | 必填，禁止通配符、路径或尾斜杠 |
| ADMIN_USERNAME | 首次管理员用户名 | 必填，非空白，最多 64 字符 |
| ADMIN_INITIAL_PASSWORD | 首次管理员密码 | 必填，至少 12 字符、最多 72 UTF-8 字节 |
| SESSION_TIMEOUT | 会话空闲有效期 | 30m |
| SESSION_COOKIE_SECURE | Cookie 是否只用于 HTTPS | 本地 HTTP false；HTTPS 部署 true |
| DB_HOST | 后端连接的 MySQL 主机 | Compose 固定注入 mysql；宿主开发需调整或覆盖 JDBC URL |

ALLOWED_ORIGINS 应包括浏览器实际使用的协议、主机、端口，例如 `http://localhost:8088,http://127.0.0.1:8088`。改变端口或 HTTPS 协议时同步调整；localhost 与 127.0.0.1 不是同一个 origin。

### 2.2 构建启动

```powershell
docker compose config --quiet
docker compose up --build -d --wait --wait-timeout 240
docker compose ps
```

首次构建需要基础镜像、Maven 和 npm 依赖。默认访问 `http://localhost:8088/login`，使用首次用户名/密码登录。默认不发布后端和数据库宿主端口。

启动顺序：MySQL 健康 → 后端迁移、初始化并健康 → 前端。后端 `/actuator/health` 用于内部健康检查，Nginx 默认不对外代理 `/actuator/`。前端 `/healthz` 仅表示前端存活，不代表数据库健康。

### 2.3 初始化及既有数据

- 管理员表为空才创建固定 id=1 的管理员，保存 BCrypt cost=12 哈希；已有管理员时保留数据库值。
- 重启或改变初始化环境变量不会覆盖已有密码。单例主键、CHECK 和重复键处理保证并发初始化不产生重复管理员。
- MySQL 卷初始化后，修改 DB_NAME/DB_USER/DB_PASSWORD 不会自动修改旧库、账号或权限。
- 升级保持原项目名、原卷及兼容配置。V2 只新增认证/Key/会话表，不删除 Skill；Flyway 迁移，Hibernate validate 验证结构。

## 3. 日常运行与升级

```powershell
docker compose ps
docker compose logs --tail 100 backend
docker compose logs --tail 100 frontend mysql
# 暂停，保留容器和卷
docker compose stop
docker compose start
# 升级前备份，再构建和重建
docker compose up --build -d --wait --wait-timeout 240
```

普通 down 删除本项目容器/网络，保留命名卷；同项目 up 可继续读取数据。不要把 `down -v`、删除卷或清库当作升级/修复凭证手段。更换项目名对应不同卷，不代表原数据被删除。

检查配置使用 `docker compose config --quiet`；完整 config 或环境 dump 可能包含密码。排错优先记录 requestId、状态码、错误 code，避免采集完整请求正文。

## 4. 宿主后端开发与前端联调

需要 JDK 21、Maven 3.9 和 Docker。在当前终端设置 JAVA_HOME 指向 JDK 21，并将其 bin 加入 PATH，避免误用系统 Java 8。

默认 Compose 不映射数据库，宿主 Maven 不能直接访问容器主机名 mysql。下面使用独立开发项目和回环端口，不改默认文件。此开发覆盖流程依据配置整理，本次文档编写未实际启动验证。

### 4.1 准备独立开发数据库

在根目录首次执行：

```powershell
python tools/new-test-env.py --output .test-output/dev.env --port 18090
@('services:', '  mysql:', '    ports:', '      - "127.0.0.1:13306:3306"') | Set-Content -Encoding utf8 .test-output/dev-db.compose.yaml
docker compose --env-file .test-output/dev.env -p skillinventory-dev -f compose.yaml -f .test-output/dev-db.compose.yaml up -d mysql --wait
```

生成器拒绝覆盖已有配置，复用时跳过生成步骤。项目 skillinventory-dev 使用独立卷；13306 被占用时调整覆盖文件及下方 JDBC URL。此时只启动 mysql，不启动 Compose 后端，避免与宿主 8080 冲突。

### 4.2 启动宿主后端

从根目录把生成配置读入当前 PowerShell 进程，不打印值：

```powershell
Get-Content -LiteralPath .test-output/dev.env | ForEach-Object {
    if ($_ -match '^([A-Z_]+)=(.*)$') {
        [Environment]::SetEnvironmentVariable($Matches[1], $Matches[2], 'Process')
    }
}
$env:DB_HOST='127.0.0.1'
$env:ALLOWED_ORIGINS='http://127.0.0.1:5173,http://localhost:5173'
$env:SESSION_COOKIE_SECURE='false'
$env:SPRING_DATASOURCE_URL="jdbc:mysql://127.0.0.1:13306/$($env:DB_NAME)?connectionTimeZone=UTC&forceConnectionTimeZoneToSession=true&characterEncoding=UTF-8&useAffectedRows=false"
Set-Location backend
mvn -B -ntp -s ../tools/maven-settings.xml spring-boot:run
```

上述解析只适用于生成器的简单 KEY=VALUE 文件，不是通用 dotenv 解析器。不要在启用环境抓取/敏感命令回显的共享终端执行。Spring Boot 不会自动读取仓库 .env，必须显式提供进程配置。

应用默认 DB_HOST 拼接固定 3306，没有单独 DB_PORT 配置，所以用标准 SPRING_DATASOURCE_URL 指定宿主 13306。后端默认 8080，另开终端按前端文档启动 Vite，浏览器通过 Vite `/api` 代理请求。

停止开发数据库时，在根目录使用相同 env、项目名和两个 Compose 文件执行 stop，保留卷。开发账号/密码在忽略目录 `.test-output/dev.env`，与正式库或认证冒烟环境不一定相同。

## 5. 管理 API 联调

### 5.1 获取会话与 CSRF

仅在有授权的本地/测试环境执行；使用交互隐藏密码输入：

```powershell
$base='http://localhost:8088'
$csrf=Invoke-RestMethod -Uri "$base/api/auth/csrf" -SessionVariable browser
$credential=Get-Credential -Message 'Skill Inventory administrator'
$loginBody=@{
    username=$credential.UserName
    password=$credential.GetNetworkCredential().Password
} | ConvertTo-Json
try {
    Invoke-RestMethod -Method Post -Uri "$base/api/auth/login" -WebSession $browser -ContentType 'application/json' -Headers @{'X-CSRF-TOKEN'=$csrf.token} -Body $loginBody | Out-Null
} finally {
    $loginBody=$null
    $credential=$null
}
$csrf=Invoke-RestMethod -Uri "$base/api/auth/csrf" -WebSession $browser
$headers=@{'X-CSRF-TOKEN'=$csrf.token}
$me=Invoke-RestMethod -Uri "$base/api/auth/me" -WebSession $browser
```

保持同一 WebSession。登录成功更新会话 ID 并清除旧 CSRF，因此再次获取 Token。管理 GET 需要 Cookie；写请求需要 Cookie、CSRF 和 JSON Content-Type，包括 DELETE。退出也需要 CSRF。

### 5.2 管理接口一览

| 方法 | 路径 | 请求/响应要点 |
| --- | --- | --- |
| GET | `/api/auth/csrf` | token、headerName |
| POST | `/api/auth/login` | username/password JSON；成功 username |
| GET | `/api/auth/me` | 当前 username |
| POST | `/api/auth/logout` | JSON `{}`；204 |
| GET | `/api/admin/skills` | keyword/status/page/pageSize；分页 |
| POST | `/api/admin/skills` | name/description/content；201 |
| GET | `/api/admin/skills/{id}` | 草稿与当前发布快照 |
| PUT | `/api/admin/skills/{id}` | description/content/lockVersion |
| POST | `/api/admin/skills/{id}/publish` | lockVersion |
| POST | `/api/admin/skills/{id}/unpublish` | lockVersion |
| DELETE | `/api/admin/skills/{id}?lockVersion=...` | 无需正文；仍需 JSON Content-Type；204 |
| GET | `/api/admin/api-keys` | page/pageSize，id 倒序 |
| POST | `/api/admin/api-keys` | name/expiresAt；201，一次性返回 metadata/key |
| POST | `/api/admin/api-keys/{id}/revoke` | JSON `{}`；metadata，幂等 |

Skill/Key 的 id 是字符串，lockVersion 是 JSON 整数。分页 `{items,page,pageSize,total}`，page 1–100000、pageSize 1–100，默认 1/20。详细字段约束见 [功能说明](01-系统功能说明.md)、[API 契约](../docs/API.md)。

### 5.3 新建与发布示例

下例写入数据，只在独立测试环境执行；沿用上节变量：

```powershell
$name='manual-' + [guid]::NewGuid().ToString('N').Substring(0,12)
$body=@{name=$name;description='操作文档联调';content='# 使用步骤'} | ConvertTo-Json
$skill=Invoke-RestMethod -Method Post -Uri "$base/api/admin/skills" -WebSession $browser -Headers $headers -ContentType 'application/json' -Body $body
$publish=@{lockVersion=$skill.lockVersion} | ConvertTo-Json
$skill=Invoke-RestMethod -Method Post -Uri "$base/api/admin/skills/$($skill.id)/publish" -WebSession $browser -Headers $headers -ContentType 'application/json' -Body $publish
```

每次写入后使用响应的新版本；409 VERSION_CONFLICT 时先读取新数据并人工合并，不自动替换版本重发。未知 JSON 字段被拒绝，不能更新 name 或提交 id、快照、时间等系统字段。

### 5.4 Key 创建及退出

推荐通过管理页面一次性展示区域创建和保存 Key。若使用 API 工具，只保留到进程内存和调用方安全配置，不打印完整创建响应。列表不可找回完整值；撤销后不能恢复。

退出：

```powershell
Invoke-RestMethod -Method Post -Uri "$base/api/auth/logout" -WebSession $browser -Headers $headers -ContentType 'application/json' -Body '{}' | Out-Null
$browser=$null
$headers=$null
$csrf=$null
```

## 6. 外部服务只读接入

管理员先发布至少一个 Skill 并发放 Key。调用方每次读取安全配置中的 Key 加到 Header，不传 query、路径或用 Cookie 替代。以下 curl 仅为占位符示意，不把真实 Key 写进 shell 历史：

```sh
curl -i -H 'X-API-Key: <从安全配置读取的Key>' 'http://部署地址/api/v1/skills?page=1&pageSize=20'
curl -i -H 'X-API-Key: <从安全配置读取的Key>' 'http://部署地址/api/v1/skills/java-code-review'
curl -i -H 'X-API-Key: <从安全配置读取的Key>' 'http://部署地址/api/v1/skills/java-code-review/SKILL.md'
curl -i -H 'X-API-Key: <从安全配置读取的Key>' -H 'If-None-Match: "<上次ETag>"' 'http://部署地址/api/v1/skills/java-code-review/SKILL.md'
```

列表只有发布元数据，JSON 详情另含完整 skillMd，原文为 UTF-8 text/plain。保留 ETag 下次重验证；304 无正文时复用对应私有缓存。不同部署/路径/Key 的缓存应隔离；旧标签不能绕过撤销和下架。

只读检查脚本使用 Python 标准库，无需 Docker 或管理员登录：

```powershell
python tools/test-skill-api.py --base-url http://127.0.0.1:8088
python tools/test-skill-api.py --base-url http://127.0.0.1:8088 --name java-code-review
```

默认隐藏输入 Key，也支持 SKILL_API_KEY 进程环境。该脚本只读，与会写入、撤销和重启容器的 smoke.py 不同。无有效 Key 或无已发布记录时不能期待通过。

### 7.1 后端测试

在 backend 目录使用 JDK 21：

```powershell
mvn -B -ntp -s ../tools/maven-settings.xml test
```

可加 `-Dmaven.repo.local=.tools/m2` 将仓库放在 backend 忽略目录。测试使用 Testcontainers 全新 MySQL 8.4.6，不读正式库，不以 H2 代替。需要 Docker 管道权限和可用镜像；无 Docker 应记录受阻，不能声称 MySQL 已验证。

### 7.2 独立认证冒烟

根目录首次生成配置，已有文件复用时跳过生成步骤：

```powershell
python tools/new-test-env.py
docker compose --env-file .test-output/auth-smoke.env -p skillinventory-auth-smoke config --quiet
docker compose --env-file .test-output/auth-smoke.env -p skillinventory-auth-smoke up --build -d --wait --wait-timeout 240
```

默认 18089、项目 skillinventory-auth-smoke，独立命名卷。脚本登录、写入/发布测试 Skill、创建/撤销 Key、验证 ETag 和退出；`--restart` 还对此明确指定的独立项目 down/up，Key 保留在进程内存，验证持久化及日志/数据库无完整凭证。不要指向正式项目，不与浏览器测试并发重启。

已有验证记录为后端 13 项、前端 11 项、Chrome 2 条及 Nginx/down-up 通过。本次编写材料没有重跑；见 [原验证记录](../docs/VALIDATION.md)。

## 8. 备份恢复与受控密码维护

### 8.1 数据库备份

备份包括 Skill、管理员哈希、Key 摘要、持久会话及 Flyway 记录，保存到仓库外受控位置。根目录 POSIX shell 示例，通过容器环境读密码，先在容器写文件，避免 Windows PowerShell 重定向编码转换：

```sh
docker compose exec -T mysql sh -c 'MYSQL_PWD="$MYSQL_PASSWORD" mysqldump -u"$MYSQL_USER" --single-transaction --no-tablespaces --set-gtid-purged=OFF "$MYSQL_DATABASE" > /tmp/skill-backup.sql'
docker compose cp mysql:/tmp/skill-backup.sql ./skill-backup.sql
```

随后将备份安全移出仓库，按维护策略清理临时副本，不输出或提交 dump。恢复先使用兼容的应用和迁移版本。

### 8.2 隔离恢复

准备独立 .env.restore、skill-restore 项目与空恢复卷，经确认只对恢复数据库导入，不覆盖使用中的库。POSIX shell：

```sh
docker compose --env-file .env.restore -p skill-restore up -d mysql --wait
docker compose --env-file .env.restore -p skill-restore cp ./skill-backup.sql mysql:/tmp/skill-backup.sql
docker compose --env-file .env.restore -p skill-restore exec -T mysql sh -c 'MYSQL_PWD="$MYSQL_PASSWORD" mysql -u"$MYSQL_USER" "$MYSQL_DATABASE" < /tmp/skill-backup.sql'
docker compose --env-file .env.restore -p skill-restore up -d --wait
```

本次材料未演练备份恢复。恢复会带入会话及 Key 状态，应按恢复环境要求受控处理会话失效和轮换，不直接将未经检查的恢复库对外开放。

### 8.3 管理员密码重置/轮换

无公开重置 API。维护员备份并停止 backend，在交互终端使用 BCrypt 工具：

```powershell
# 根目录；替换实际 Maven jar 路径，Windows classpath 用分号
& "$env:JAVA_HOME/bin/java.exe" -cp '<crypto-jar路径>;<spring-jcl-jar路径>' tools/PasswordHash.java
```

当前依赖为 crypto 6.5.11、spring-jcl 6.2.19，可在实际 Maven 仓库找 jar。工具两次隐藏输入，至少 12 字符、最多 72 UTF-8 字节，只输出哈希；哈希也需保管。

通过交互 MySQL 管理连接（例如 `docker compose exec mysql mysql -uroot -p`）输入数据库管理密码，选择实际应用库，在受控维护窗口执行占位 SQL：

```sql
START TRANSACTION;
UPDATE administrator SET password_hash='<新的BCrypt哈希>' WHERE id=1;
DELETE FROM SPRING_SESSION;
COMMIT;
```

确认目标库和记录正确、UPDATE 影响行数为 1，再提交。清会话使旧登录失效，属性表级联清理，不删管理员、Key 或 Skill。重启 backend 并用新密码登录。改 ADMIN_INITIAL_PASSWORD 无法重置已有管理员；本次未在真实库执行重置。

数据库账号密码轮换是另一流程：管理员交互执行 ALTER USER，更新部署配置并重建应用；改 MYSQL_PASSWORD 环境变量不会更新已有 MySQL 用户。

## 9. 排错索引

| 状态/现象 | 检查顺序 |
| --- | --- |
| 后端连接失败/unhealthy | MySQL 健康、DB_HOST/JDBC URL、端口、库名、凭证和权限，保留旧卷 |
| Flyway 校验失败 | 已执行迁移是否被改写、应用版本与结构是否兼容，不手改 checksum 或清库 |
| 首次管理员配置错误 | 空值、用户名长度、密码字符数/UTF-8 字节数，区分首启和已有管理员 |
| 管理 401 | 同一 Cookie 是否保持、登录是否成功、会话是否过期，Key 不代替 |
| 客户端 401 | Header、错误/过期/撤销 Key；会话和 query 不代替 |
| 403 | code、登录后 CSRF 更新、Origin/Sec-Fetch-Site，不关闭全局 CSRF |
| 400 | JSON 类型、未知字段、名称、正文、长度、时间、分页 |
| 404 | 有效 Key 下检查发布状态/名称，管理详情检查 ID |
| 409 | 区分 NAME_CONFLICT、VERSION_CONFLICT、PUBLISHED_DELETE，按业务处理 |
| 413/415 | 请求体上限、管理写请求 JSON Content-Type |
| 429 | 登录窗口限流，等待恢复，不把重启当常规解锁 |
| 500 | requestId、异常类型和数据库可用性，不输出凭证/SQL 参数/正文 |
| 登录成功后仍 401 | Cookie 发送、Secure 与 HTTP 匹配、域名路径、持久会话读写 |

来源/媒体/大小检查可先于认证拒绝恶意或格式错误请求，不应把所有拒绝都解释为登录失败。跨不可信网络必须 HTTPS 并启用 Secure Cookie，仓库未内置 TLS 证书或公网网关方案。
