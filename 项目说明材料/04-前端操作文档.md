# 前端操作文档

适用版本：2026-10-19 当前工作区。第一部分面向管理员网页使用，第二部分面向前端开发与联调。默认正式编排入口 `http://localhost:8088`；实际地址由部署人员提供。

## 1. 登录、退出和页面导航

1. 打开系统地址。未登录访问管理页会进入 `/login`。
2. 输入部署人员配置的管理员用户名和密码，点击“登录”，等待提交完成。
3. 登录成功回到原站内管理页；无原目标时进入 Skill 列表。外站地址不作为跳转目标。
4. 页头显示管理员用户名，通过“API Key 管理”进入凭证页，通过“Skill Inventory”返回目录。
5. 操作完成点击“退出”，服务端会话失效。页面没有注册、找回密码或修改密码入口；需要重置时联系维护员。

错误密码统一提示“用户名或密码错误”；连续尝试触发节流时等约一分钟再试。不要用修改 `.env` 的初始密码来替代已有管理员的重置流程。

| 页面 | 路径 | 用途 |
| --- | --- | --- |
| 登录 | `/login` | 单管理员认证 |
| Skill 列表 | `/` | 查询、筛选、发布/下架/删除、复制 |
| 新建 | `/skills/new` | 创建草稿 |
| 编辑 | `/skills/{数字ID}` | 编辑、预览、保存、发布、下架 |
| Key 管理 | `/api-keys` | 创建、分页查看、撤销 Key |

## 2. 查询 Skill

在列表输入 name 或描述关键词，选择“全部状态/未发布/已发布/有未发布修改”，点击“查询”。更改筛选重新从第一页查询；可选每页 20、50 或 100 条，用上一页/下一页翻页。

列表名称、描述来自当前草稿；更新时间按浏览器本地时区显示。状态含义见 [系统功能说明](01-系统功能说明.md)。点击 Skill 名称或“编辑”进入详情。

“复制 name”复制稳定名称；已发布记录可“复制发布地址”。复制的是地址，不包含 Key；直接在普通浏览器标签页打开该地址会缺少 `X-API-Key`，通常返回 401。

## 3. 创建和编辑

1. 点击“＋ 新建 Skill”。
2. 填写 name，例如 `java-code-review`。只能小写字母、数字和单连字符，最多 64 字符，创建后不能修改。
3. 填写 description，说明用途与适用场景，非空白、最多 1024 个 UTF-16 字符单元。
4. 在“编辑草稿”中填写 Markdown 正文。不要粘贴开头的 `---` YAML 元数据块，后端自动生成 name/description frontmatter。
5. 右侧“草稿预览”随输入更新；原始 HTML 和图片不会作为普通 Markdown 内容渲染执行。
6. 点击“保存草稿”。成功后新建页面变为持久化详情地址；新记录仍未发布。

“填入初始模板”会确认后替换当前正文；不是自动合并。正文必须非空白、UTF-8 不超过 262144 字节，页面显示实时字节数，中文和 emoji 可能占多个字节。

编辑已有 Skill 时 name 为只读。正文和描述保存到草稿，正在对外分发的快照保持原样。页面没有自动保存；关闭页面前应显式保存。

## 4. 发布、下架和删除

### 4.1 发布

1. 先点击“保存草稿”，确认保存成功。
2. 点击“发布已保存草稿”，阅读确认信息后发布。
3. 状态成为“已发布”，外部服务开始读取该快照。
4. 切换“当前发布快照”可预览已发布正文与元数据，不需要浏览器使用 API Key。

有未保存输入时，编辑页会要求先保存；直接在列表点击发布，只会发布服务端已经保存的草稿，不会带上其他标签页中尚未提交的内容。发布同一内容不额外制造发布版本。

### 4.2 下架

点击“下架”并确认。服务端清除发布快照、保留草稿；外部详情/原文返回 404，发布列表不再包含该记录。已经下载到调用方的副本不会被远程撤销。

### 4.3 删除

删除在列表进行，只对没有发布快照的记录显示。已发布记录先下架，再点击“删除”并确认。删除是物理删除，页面没有回收站、撤销删除或历史版本恢复。删除后再用相同 name 创建，是新的记录 ID。

## 5. API Key 管理

### 5.1 创建与一次性展示

1. 打开“API Key 管理”。
2. 输入名称（非空，最多 100 字符），可选未来的过期时间。页面按本地时间输入，再转换为 ISO 时间提交；不填表示不过期。
3. 点击“创建 Key”。完整 Key 只在创建成功时显示一次。
4. 立即点击“复制 Key”，保存到调用方安全配置。列表只展示脱敏标识，没有“再次查看完整 Key”。
5. 点击“关闭并清除”。尚未关闭一次性展示时，创建按钮禁用；离开或刷新页面后也不能找回该 Key。

复制失败时在一次性区域手动复制，再确认保存。不要把完整 Key 拼到浏览器 URL、代码库、截图或日志中。Key 不会内置进前端构建产物。

### 5.2 查看、轮换和撤销

列表每页 20 条，按新建 ID 倒序，显示名称、脱敏标识、ACTIVE/EXPIRED/REVOKED、创建/过期/撤销时间。没有改名、修改有效期或恢复功能。

撤销前确认提示会中断调用方，确认后下一请求即不再接受该 Key。已经撤销的 Key 不能恢复；重复撤销不改变原撤销时间。轮换应“新建 → 更新调用方 → 验证读取 → 撤销旧 Key”。丢失则按同样步骤重建，不要先撤销仍在使用的唯一凭证。

## 6. 会话失效、冲突和常见问题

| 现象 | 原因/处理 |
| --- | --- |
| 提示登录失效，编辑页面仍在 | 先复制未保存内容作为保护；按提示在新标签页登录，回原页点击“重新连接并保留输入”，再手动重试。不要直接刷新原编辑页 |
| 403，提示 CSRF 或权限问题 | 前端会尝试更新 CSRF，但不自动重放写请求；确认已重新登录再重试。若 code=ORIGIN_DENIED，联系部署人员检查 Origin/协议/端口 |
| 409 VERSION_CONFLICT | 其他请求已改变版本；输入仍保留。先复制所需内容，再确认“放弃本地输入并刷新”，读新版本后手动合并保存 |
| 409 name 冲突或已发布不能删除 | 使用其他 name，或先下架；并非所有 409 都是版本冲突 |
| 400 | 检查名称、空白内容、字节长度、frontmatter、Key 过期时间等 |
| 413 | 完整请求体超过 2 MiB，缩小内容；正文另有更小限制 |
| 复制发布地址后打开 401 | 地址是外部接口，需要 Header Key；管理员登录不能替代 |
| 404 发布接口 | 检查名称是否存在、是否已发布或已下架；Key 无效通常为 401 |
| 网络错误/500 | 保留输入与 requestId，检查服务连通性或联系维护员，不反复覆盖提交 |

编辑页在离开路由或关闭浏览器时对未保存输入提供提醒。这是内存中的保护，不是本地持久化草稿；浏览器崩溃、强制关闭或确认丢弃仍可能丢失输入。

## 7. 前端开发环境

需要 Node ≥22.12 和 npm；固定依赖以 package-lock 为准。后端需准备可用 MySQL、允许的开发 Origin，并在宿主机 `127.0.0.1:8080` 提供 API。如何启动宿主后端见 [后端文档第 4 节](05-后端操作文档.md)。

在仓库根目录执行：

```powershell
Set-Location frontend
npm ci
npm run dev
```

打开 Vite 输出的实际地址，通常为 `http://127.0.0.1:5173`。脚本显式绑定 127.0.0.1，`vite.config.ts` 把 `/api` 代理到 `http://127.0.0.1:8080`。如果默认端口被占用，使用输出的新端口并同步后端 ALLOWED_ORIGINS；localhost 与 127.0.0.1 也必须分别配置。

完整 Compose 默认不把 backend:8080 映射给宿主，因此“只启动 Compose 再启动 Vite”不能自动连接其内部后端。可以使用后端文档的独立开发数据库 + 宿主后端方案；不要为了联调修改默认生产端口边界。

前端没有独立的 API Key 构建环境变量。不要在 `VITE_*` 配置或源码中放管理会话、密码或 API Key。

## 8. 前端测试与构建

在 frontend 目录执行：

```powershell
npm test
npm run build
```

`npm test` 为 Vitest/JSDOM；`npm run build` 先 vue-tsc 类型检查，再 Vite 打包，产物在 frontend/dist。没有单独配置 npm lint 命令。开发模式没有 Nginx 的完整生产 CSP 与代理配置，组件测试不代表真实部署表现。

真实浏览器测试需先按后端文档启动独立认证冒烟项目。确认重启冒烟已结束、服务健康，再从 frontend 运行：

```powershell
$env:E2E_BASE_URL='http://127.0.0.1:18089'
$env:BROWSER_CHANNEL='chrome'
npx playwright test
```

Chrome channel 需要本机安装 Chrome；也可安装 Playwright Chromium 并不设置该 channel。测试默认基础地址实际是 18088，认证隔离环境生成器默认是 18089，所以此处必须显式设置 E2E_BASE_URL。

测试从 `.test-output/auth-smoke.env` 读取测试账号，或从 E2E_ADMIN_USERNAME/E2E_ADMIN_PASSWORD 进程环境读取。使用其他测试环境时要提供相应测试凭证，不把密码写进命令历史或文档。测试会新建随机名称记录和 Key，并执行发布、下架、删除、撤销及退出；仅对独立测试环境运行，不与 smoke.py 的 down/up 并行。

## 9. 开发维护入口

| 文件 | 修改场景 |
| --- | --- |
| [main.ts](../frontend/src/main.ts) | 路由、登录守卫 |
| [api.ts](../frontend/src/api.ts) | 请求、CSRF、错误、401 会话事件与 403 Token 刷新 |
| [App.vue](../frontend/src/App.vue) | 页头、退出、会话失效与重新连接 |
| [Editor.vue](../frontend/src/Editor.vue) | 草稿基线、脏状态、预览、版本冲突保护 |
| [ApiKeys.vue](../frontend/src/ApiKeys.vue) | 一次性明文展示、清除、列表与撤销 |
| [markdown.ts](../frontend/src/markdown.ts) | 安全渲染 |
| [nginx.conf](../frontend/nginx.conf) | SPA history 回退、API 代理、CSP、2 MiB 限制 |

管理写请求统一通过 api.ts，保持 `credentials: same-origin` 和 CSRF 头，不使用 localStorage 凭证。新增页面若需要公共访问，要同时考虑路由和服务端安全规则；前端守卫本身不提供服务端授权。

已有验证数量与范围见 [材料总览](README.md) 和 [原验证记录](../docs/VALIDATION.md)。本次文档编写没有再次执行上述测试。
